D001 · LEDGER를 최종 설계가 아닌 후보로 취급

provisional

이유

사용자의 최신 지시. 가장 방어 가능한 현상을 먼저 찾는다.

대안

기존 C1/C2/C3와 paced를 고정 구현

현재 선택하지 않은 이유

결론을 맞추는 방향으로 탐색이 편향될 수 있다.

D002 · 첫 독립 도구 후보는 공식 FEMU BlackBox

provisional

이유

ftlsim과 다른 구현의 device-managed FTL과 native counter를 사용할 수 있다.

대안

MQSim, 자체 simulator, 실제 장치 SMART

현재 선택하지 않은 이유

MQSim은 보고서의 문제가 독립 확인되지 않았고, 자체 모델은 독립성이 부족하다. SMART의 host bytes는 NAND/erase를 대신하지 못한다.

D003 · Windows/WSL에서는 FEMU 설치·실행을 보류

active-environment-gate

이유

공식 요구사항에서 WSL은 지원하지 않으며 관측한 WSL에 /dev/kvm도 없다.

대안

WSL nested KVM 또는 TCG로 강행

현재 선택하지 않은 이유

실행 편의를 위해 latency validity를 포기하지 않는다.

D004 · 집 개발과 연구실 실행을 같은 Git/config로 연결

active-remote-connected-runtime-blocked

이유

장비 위치를 바꿔도 코드와 실험 조건을 추적할 수 있다. 사용자가 연구실 접속을 요청했다.

대안

집 물리 Ubuntu 설치/듀얼부팅

현재 선택하지 않은 이유

여전히 가능하지만 지금 OS 설치·재부팅·파티션 변경은 요청되지 않았다.

D005 · 4 GiB raw / 3 GiB exposed를 첫 후보로 기록

provisional-runtime-unvalidated

이유

4 KiB page, 256-page block, 256 GC lines를 유지하며 작은 모델의 비용을 줄인다.

대안

default 16 GiB raw / 12 GiB exposed 또는 2 GiB raw

현재 선택하지 않은 이유

default는 16 GB host에 크고, 더 작은 모델은 GC granularity 영향을 더 키울 수 있다. runtime 검증 전에는 확정하지 않는다.

D006 · JSON에서 HTML 설명을 생성

active

이유

측정하지 않은 숫자를 실측처럼 보여주거나 결과와 설명이 어긋나는 일을 막는다.

대안

HTML에 숫자를 직접 편집

현재 선택하지 않은 이유

반복·팀 공유에서 source of truth가 둘로 갈라질 수 있다.

D007 · 공용 서버 기본 설정을 변경하지 않음

active-runtime-blocker

이유

사용자 지시: 서버에서는 계정의 ledger 폴더 안에서만 작업한다. /dev/kvm 접근 권한은 현재 없다.

대안

sudo 실행, kvm group/ACL 변경, 시스템 dependency 설치, TCG 우회

현재 선택하지 않은 이유

공용 설정 변경은 금지됐고 TCG는 지원 KVM 환경의 latency 검증을 대신할 수 없다. Python venv도 device 권한은 해결하지 못한다.

새로운 질문을 발견하면

  • 같은 LBA 순서에서 요청 크기만 바꿔도 GC 호출 시점 때문에 내부 비용이 달라질까?
  • logical fill과 raw NAND의 live occupancy 중 어느 값이 rate를 더 잘 설명할까?
  • 회계로 공정하게 비용을 나누는 것보다 배치로 그 비용 자체를 줄이는 것이 더 강한 해결일까?
  • KV를 덜 저장하면 재계산으로 늘어난 시간 동안 로그·DB가 더 쓰는 비용까지 줄어들까?

생성 원본: records/*.json · config. HTML은 설명 layer이며 실측 원본은 JSON/CSV/log입니다. 기존 연구 HTML은 별도 원본입니다.
