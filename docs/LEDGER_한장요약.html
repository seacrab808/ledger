01

무엇이 일어나는가 — 한 그림

문제

서로 독립적인 서비스들이 플래시 수명을 함께 소모한다. 학습은 메모리가 모자랄 때 쓰기로 버틴다.

갭

cgroup은 바이트를 세지만 소거를 모르고, 대리 쓰기(journald·zram)는 원인 서비스에 귀속되지 않으며, 누적 예산이 없다.

기여

소거 비용 귀속 + 누적 예산 + 환율. 학습 서비스만 쓰기를 연산으로 되살 수 있다는 성질을 이용한다.

02

Figure 1 — 게이트. 이 그림이 논문의 첫 그림이다

측정 전이다. 아래는 형태 예상이며 축과 범례만 확정한다. 10.03까지 실측으로 대체한다.

통과

압박 유발 소거(zram·오프로드)가 1 GB 캡에서 총 소거의 20% 이상 → 주장 성립. 예산·환율 설계로 진행.

실패

20% 미만 → 지배 쓰기는 모델 저장·로그. 주장을 "학습 라운드가 서비스별 소거 예산을 태운다"로 좁히고, 노브는 저장 주기·크기로 바꾼다.

측정 방법 — systemd 슬라이스에 memory.max 캡 → LoRA 1 라운드 → cgroup io.stat wbytes, /sys/block/zram0/bd_stat(bd_writes), NVMe SMART Data Units Written 수집 → blkparse → MQSim 재생으로 소거 환산.

03

통찰 → 메커니즘

관찰메커니즘재사용새로 만드는 것
바이트 ≠ 소거. 작은 랜덤 쓰기·flush는 순차 스필보다 바이트당 소거가 크다서비스별 WAF로 보정한 소거 비용blktrace, cgroup io.statblkparse→MQSim 변환기, 패턴별 WAF 표
대리 쓰기는 쓴 주체에 귀속된다대리 쓰기별 훅커널의 writeback cgroup 귀속(그대로)journald _SYSTEMD_CGROUP 매핑, SQLite uprobe, zram 슬롯→swap_cgroup 룩업
누적 예산이 없다유저스페이스 원장 + 기존 노브로 집행memory.low/min, io.max, PSI원장 데몬. 새 cgroup 컨트롤러 없음
학습만 쓰기를 연산으로 되살 수 있다환율 — 소거 통화 하나로MADV_FREE, gradient checkpointinggradient checkpointing 깊이 노브, 라운드별 예산 보고 → FL 서버 선택
스필: E_spill = bytes × WAF(service) / erase_block      재계산: E_recompute = 0 (소거)    제약: T_recompute ≤ T_budget
결정: 재계산 ≤ 예산 지연이면 재계산, 아니면 스필. 통화는 소거 하나. 지연은 제약이지 비용이 아니다.
04

지금 만들 것 — 테스트 전에

Figure 1에 필요한 것은 b1·b2·b3다. b4·b5·b6은 게이트 이후 단계이며 병행한다. 10.03에 합친다.

memory.max 스윕 스크립트(8/4/2/1 GB).

라운드 전후 io.stat·zram bd_stat·SMART 스냅샷.

플롯 스크립트.

완료 기준: 캡 4개 × 3회 반복 CSV와 Figure 1 초안.

Flower 클라이언트 안의 LoRA(0.5B, CPU).

gradient checkpointing 깊이 노브.

라운드당 쓰기 로그.

가중치는 anon으로 적재하거나(mmap 읽기 전용이면 압박이 clean 페이지 축출로 새어 소거 0), 캡을 가중치 크기 대비로 잡는다(0.5B bf16 ≈ 1 GB).

완료 기준: 1 라운드가 1 GB 캡에서 죽지 않고 끝난다.

blkparse → MQSim 트레이스 변환기.

NVMe SMART Data Units Written(호스트 바이트)과 벤더 NAND 쓰기 로그로 WAF 산출 — RPi 5 드라이브가 NAND 쓰기 카운터를 노출하는지 1주차에 확인.

완료 기준: 같은 트레이스에서 MQSim WAF와 SMART WAF가 ±20% 안. 카운터가 없으면 MQSim 단독, 문서에 명시.

block_bio_queue·writeback에 상시 attach, cgroup별 플래그로 비싼 룩업 게이트.

zram 슬롯→swap_cgroup 프로토타입 먼저(가장 위험).

게이트 측정은 슬라이스 하나라 cgroup 귀속이 필요 없다 — 쓰기 경로별 분리(zram bd_stat, 저장 파일, 저널)로 충분하다.

완료 기준: 바이트 수를 아는 합성 writer 4종에서 귀속 합 = io.stat 총량, 잔차 명시.

Flower 서버.

클라이언트가 라운드마다 소거 소비·잔여 예산 보고.

예산 하 클라이언트 선택 + 공정성 목적함수.

완료 기준: 호스트 cgroup 클라이언트 8개로 10 라운드, 선택 로그.

stock cgroup(예산 없음), zram writeback_limit, io.max 스로틀, tmpfs 캐시 + volatile 로그.

완료 기준: 네 설정 모두 같은 하니스에서 돈다.

커널 패치 없음. 프로브·데몬·변환기·스크립트뿐이다. 이 경계를 넘는 순간 12월 1일은 없다.
